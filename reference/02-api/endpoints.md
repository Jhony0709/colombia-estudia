# 02 — API (MVP)

## Convenciones

- **Rutas de API en inglés** (`/api/learn/lessons`), como el código. Las URLs de la UI
  (`/aprender/tema/…`) siguen en español porque las ven los estudiantes.
- Route handlers bajo `app/api/**`. Server Actions solo para mutaciones que nacen en un
  formulario de la misma página y no las llama nadie más; si un job, el importador o una
  app futura lo va a necesitar, es un route handler.
- Todo handler va envuelto: `withCapability('lesson.read', { load, scopeOf })(handler)`. El
  wrapper resuelve persona, institución (desde el host), matrículas y capacidades **con
  alcance**, carga el recurso y verifica que su alcance esté permitido. Nada de
  `if (role === …)`. Test por endpoint con recurso: "misma institución, otra cohorte → 403".
- Errores con `APIError(message, status, code)`. Catálogo en `errors.md`.
- Inputs con Zod. Ids validados como cuid antes de tocar la BD. Emails normalizados.
- El serializador quita lo que el rol no debe ver (segunda línea, no autorización).
- Respuestas: `{ data }` o `{ error: { code, message, details? } }`. El cliente recibe el
  contenido, no el sobre.
