# 08 — Variables de entorno

Entornos: `local` (tu máquina, **contra el proyecto Supabase de staging**; sin Supabase CLI),
`staging` (Vercel: Production y Preview mientras no exista producción) y, cuando el producto
esté listo, `prod` (proyecto Supabase Pro aparte). Los tests de integración no usan ninguno de
los tres: corren contra un Postgres plano local o el service container del CI, con las variables
pasadas en la línea de comando. Nada de datos reales fuera de producción. `prisma migrate deploy`
corre en CI sobre `main` antes del deploy, nunca a mano contra un entorno remoto.

| Variable                                             | Requerida | Entornos               | Dónde se usa                                                                                                                                                                                                                                                                        |
| ---------------------------------------------------- | --------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                                       | Sí        | todos                  | Prisma en runtime: transaction pooler, puerto 6543, `?pgbouncer=true&connection_limit=1`, usuario `prisma.<project-ref>`                                                                                                                                                            |
| `DIRECT_URL`                                         | Sí        | todos                  | `prisma migrate deploy`: session pooler, puerto 5432 (la conexión directa exige IPv6 o el add-on IPv4)                                                                                                                                                                              |
| `NEXT_PUBLIC_SUPABASE_URL`                           | Sí        | todos                  | Cliente Supabase Auth                                                                                                                                                                                                                                                               |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`               | Sí        | todos                  | Cliente Supabase Auth (llave `sb_publishable_…`, sucesora de `anon`; las llaves JWT `anon`/`service_role` quedan deprecadas a fin de 2026). Mapea al rol `anon`: **RLS deniega todo a este rol**                                                                                    |
| `SUPABASE_SECRET_KEY`                                | Sí        | todos                  | Solo servidor (llave `sb_secret_…`, sucesora de `service_role`; salta RLS y Supabase la rechaza desde un navegador): Storage firmado, invitaciones, anonimización. **Jamás al cliente**                                                                                             |
| `NEXT_PUBLIC_APP_URL`                                | Sí        | todos                  | URL base para enlaces cuando no hay institución en contexto (verificación de certificados; logo del recordatorio de cuota si la institución no tiene `primaryDomain`); el tenant se resuelve por `Institution.primaryDomain`                                                        |
| `RESEND_API_KEY`                                     | Sí        | staging, prod          | Emails. El remitente sale de `Institution.emailFromName` sobre el dominio verificado                                                                                                                                                                                                |
| `EMAIL_DOMAIN`                                       | Sí        | staging, prod          | Dominio verificado en Resend (`albafuturoeducativo.com`, 8/10). Remite `no-reply@` ese dominio; ver `docs/runbooks/dominio-y-correo.md`                                                                                                                                             |
| `VIMEO_ACCESS_TOKEN`                                 | Sí        | staging, prod          | Metadatos y pistas de subtítulos al registrar videos                                                                                                                                                                                                                                |
| `CRON_SECRET`                                        | Sí        | staging, prod          | Firma del job diario (`POST /api/jobs/daily`); distinto por entorno                                                                                                                                                                                                                 |
| `BOLD_API_KEY`                                       | Sí        | staging (prueba), prod | Llave de identidad de Bold: crea links de pago y consulta pagos. Sin ella (y sin `BOLD_SECRET_KEY` fuera de pruebas) el pago en línea no se ofrece                                                                                                                                  |
| `BOLD_SECRET_KEY`                                    | Sí        | prod                   | Llave secreta: verifica `x-bold-signature` en el webhook                                                                                                                                                                                                                            |
| `BOLD_SANDBOX`                                       | No        | staging                | `true` con las llaves de prueba: Bold firma los eventos con llave vacía. Se ignora en producción (`VERCEL_ENV=production`)                                                                                                                                                          |
| `BOLD_API_URL`                                       | No        | —                      | Por defecto `https://integrations.api.bold.co`                                                                                                                                                                                                                                      |
| `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`  | No        | staging, prod          | WhatsApp Cloud API: token de un usuario del sistema y el id del número del negocio. Sin los dos no se escribe por WhatsApp y el aviso queda solo en la plataforma                                                                                                                   |
| `WHATSAPP_APP_SECRET`                                | No        | staging, prod          | Firma `X-Hub-Signature-256` del webhook `/api/webhooks/whatsapp` (secreto de la app en Meta)                                                                                                                                                                                        |
| `WHATSAPP_VERIFY_TOKEN`                              | No        | staging, prod          | El token que se escribe en Meta al suscribir el webhook                                                                                                                                                                                                                             |
| `WHATSAPP_BUSINESS_PHONE`                            | No        | staging, prod          | El número del negocio en dígitos (`57301…`) para los enlaces `wa.me`; sin él, el teléfono de soporte de la institución                                                                                                                                                              |
| `WHATSAPP_TEMPLATE_ATTEMPT_GRANTED`                  | No        | prod                   | Plantilla aprobada en Meta (`{{1}}` nombre, `{{2}}` examen) para avisar «otra oportunidad» pasadas 24 h de su último mensaje                                                                                                                                                        |
| `WHATSAPP_TEMPLATE_NEW_CHAT`                         | No        | prod                   | Plantilla `nuevo_chat` (`{{1}}` nombre, `{{2}}` número; botón «Tomar chat» a `/mensajes/{{1}}`) que avisa a quienes atienden cuando alguien pide un asesor. Sin ella, solo el aviso en la plataforma                                                                                |
| `WHATSAPP_TEMPLATE_FOLLOW_UP`                        | No        | prod                   | Plantilla aprobada en Meta (`{{1}}` nombre) para retomar un chat de `/mensajes` pasadas 24 h de su último mensaje. Sin ella, la bandeja solo avisa que no se le puede escribir                                                                                                      |
| `WHATSAPP_TEMPLATE_NEW_REQUEST`                      | No        | prod                   | Plantilla `nueva_solicitud` (`{{1}}` nombre, `{{2}}` curso; botón a `/solicitudes`) que avisa a `whatsappAgentPhones` de una solicitud de matrícula (23/11). Sin ella, solo el aviso en la plataforma                                                                               |
| `WHATSAPP_TEMPLATE_LANGUAGE`, `WHATSAPP_API_VERSION` | No        | —                      | Por defecto `es_CO` y `v23.0`                                                                                                                                                                                                                                                       |
| `SENTRY_DSN`                                         | Sí        | staging, prod          | Errores desde el primer handler                                                                                                                                                                                                                                                     |
| `TZ`                                                 | Local/CI  | local, CI              | `America/Bogota`. **En Vercel no se puede: `TZ` es una variable reservada** y sus runtimes corren en UTC. No es un problema: la zona horaria está explícita en el código (`packages/domain/src/dates.ts` y `apps/web/lib/mail/templates/invitation.ts`), nada lee la TZ del proceso |

`.env.example` lleva todas con placeholder. `.env*` nunca se commitea. Webhooks: Bold (18/11) y WhatsApp (5/11).
